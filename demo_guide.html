ESP32 Automated Sentry Turret

Science Fair 2026 — Grade 8 — Demo Guide

Before You Start — Checklist

  • 1
    Run the flash fix Open Git Bash and run: bash ~/ESP32/fix_flash_wp.sh
  • 2
    Upload the main sketch Open ESP32_Sentry_Turret.ino in Arduino IDE and click Upload
  • 3
    Load a Nerf dart Insert one dart into the Nerf Jolt before powering on
  • 4
    Set up the demo area Place the turret on a table. Clear a 1–2 metre zone in front of it
  • 5
    Turn on the battery pack Powers the pan and tilt servos (MG996R). Make sure the ground wire connects to ESP32 GND

Demo Steps

1

Power On

Plug in the ESP32. The green LED starts blinking — PIR sensor is warming up (10 seconds).

The system is powering on. The green light blinking means the PIR motion sensor is warming up — it needs a few seconds to calibrate to the room temperature.
2

System Armed

After 10 seconds the green LED goes solid. Turret centers itself at 90°.

The green light is now solid — the turret is armed and waiting for motion.
3

Trigger the PIR

Walk into the detection zone. The buzzer beeps twice and the green LED turns off.

I just walked into the detection zone. The PIR sensor detected my body heat and triggered the alarm.
4

Scanning

The pan servo sweeps left to right while the ultrasonic sensor pings for targets.

Now the turret is scanning. The pan servo rotates the ultrasonic sensor across the room. It sends out a sound pulse and listens for the echo — like a bat — and calculates the distance at every angle.
5

Target Locked

The turret snaps to your angle. Tilt adjusts based on distance (close = tilt down, far = tilt up).

Target locked. It found the closest object and calculated which angle I’m at. The tilt servo also adjusted based on distance — close targets tilt down, far targets tilt up.
6

Fire

Three short beeps, one long beep, then the trigger servo fires the dart.

Three warning beeps, then fire. The trigger servo pulls the Nerf gun trigger, launches the dart, and then releases.
7

Cooldown & Reset

Turret returns to center, waits 3 seconds, green LED comes back on. Now reload and repeat.

The system goes into cooldown — I’d reload the dart here — and then it automatically re-arms and is ready to detect the next target.

Serial Monitor Commands

Baud: 115200  |  Line ending: Newline

Command What it does When to use it
A Toggle auto mode ON / OFF Stop the turret from looping
R Reset to IDLE, servos return to center Restart demo from the beginning
M Force start a scan (skips PIR) PIR doesn't trigger on its own
F Force fire immediately Manual fire for demo
D Read and print current distance Check ultrasonic sensor is working
P Print current state, angle, distance, mode Debug what the system thinks it's doing
T[angle] Move tilt servo to angle Manually aim tilt (e.g. T90, T120)

If Something Goes Wrong

Problem Fix
Turret stuck in a loop Type A in Serial Monitor to turn off auto mode
PIR doesn't trigger Type M to force-start the scan manually
Dart doesn't fire Type F to force fire, check dart is loaded
Pan servo not moving Check battery pack is ON and ground wire connects to ESP32 GND
Upload fails (MD5 mismatch) Run bash ~/ESP32/fix_flash_wp.sh then re-upload
ESP32 won't connect Unplug → hold BOOT → plug in → release BOOT after 2s

Science Fair Speech (~2 minutes)

Hi, my name is [Name], and my project is an Automated Sentry Turret built using an ESP32 microcontroller.

The question I explored was: Can a low-cost microcontroller be programmed to detect, track, and respond to a moving target automatically?

My turret uses three sensors. First, a PIR — or Passive Infrared — sensor detects body heat when a person enters the area. That wakes the system up. Second, an HC-SR04 ultrasonic sensor, mounted on a servo motor, sweeps across the room sending out sound pulses and measuring how long the echo takes to come back. This tells the system the distance to any object at each angle. Third, the system calculates which angle has the closest target and aims at it.

Once it’s aimed, a second servo adjusts the tilt — up for far targets, down for close ones. Then a third servo pulls the Nerf gun trigger.

The whole system runs as a state machine — five states: Idle, Scanning, Targeting, Firing, and Cooldown. Each state has specific rules and transitions. This is how real-world systems like security cameras and autonomous robots are designed.

What I learned is that hardware and software have to work together very precisely. I ran into problems like flash chip write-protection, servo timing conflicts, and sensor noise. Debugging those problems taught me more than the programming itself.

For future improvements, I’d add a camera with computer vision to identify people versus objects, and a servo-controlled reload mechanism so it can fire multiple times automatically.

Thank you — I’m happy to answer any questions or give you a live demo.
